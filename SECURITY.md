# Security policy

## Reporting a vulnerability

Do not open a public issue for a security problem.

Use GitHub's private vulnerability reporting on the repository's **Security**
tab. Include:

- affected version or commit;
- platform and build type;
- reproduction steps or a proof of concept;
- impact and any suggested fix.

You should receive an acknowledgement within a few days. This is a volunteer
project, so there is no guaranteed SLA. Please allow time for a fix before
public disclosure.

## Scope

In scope: the desktop editor, its local file handling, import/export pipeline,
the static website, and build/release configuration.

Out of scope: vulnerabilities in third-party providers and FFmpeg builds supplied
by your distribution.
